# 配图路线选择：可灵 / 本机固定卡通人物 / 静帧运镜

一首歌配画面有三条路。**先按预算和用途选路，再动手** —— 三条路产出形态完全不同，中途换会废掉已做的活。

## 三条路

| | A 可灵图生视频 | B 本机固定卡通人物 | C 静帧运镜（保底） |
|---|---|---|---|
| 输入 | 已有分镜图当首帧 | 只给文字描述 | 已有分镜图 |
| 产出 | 5–10 秒真视频（人在动） | 静态图 + ffmpeg 推拉 | 静态图 + ffmpeg 推拉 |
| 成本 | ¥0.6–0.8/秒 → 130 s 约 ¥78–104 | **¥0** | ¥0 |
| 出片速度 | 17 段 40–60 分钟（云端排队） | 17 张约 **42 秒**（2.5 秒/张） | 编码 22 秒 |
| 改稿成本 | 改一句提示词要花钱重跑 | 改一句免费重跑 5 秒 | 免费 |
| 人物一致性 | 首帧锁定，最稳 | 具体角色串锁定，实测够用 | 同 B |
| 动态细节 | 雨滴滑落、肩膀起伏、镜头推移 | 只有推拉 | 只有推拉 |

## 怎么选

- **MV 主打 → A**，但只做 3 个关键镜头验证（情绪爆点、群像、最难那个场景），约 ¥10；验证通过再放量。观众看 MV 要的是「动」，静帧运镜骗不过去。
- **预算紧 / 要先验证市场 → B 全量**。17 张几十秒出完，先发出去看数据。
- **给讲解类/真人出镜节目供图 → B**。本机出的厚涂和讲解节目的视觉贴得住；可灵出的是电影感，贴不上。
- **最省的组合 → A 只做 3 镜 + B 补满**，总成本压到 ¥10 以内。

## B 路线的关键：角色串要具体到能被画出来

固定 STYLE 前缀 + 固定角色描述串，**每张一字不改地贴同一串**。串里必须有：发色与发缝、胡茬、黑眼圈、脸型、上衣颜色、身体比例（头身比）。

这样写出来实测 4/4 张同一人，**不需要再走 Qwen-Image-Edit 统一**。写成「一个中年男人」这种泛描述才会张张换脸。

## B 路线做不了「真动」—— 本机图生视频的硬件天花板

被问「本机是不是生成不了视频」时，答案要分两层说清：**能生成，但出不了能用的质量。** 以下是实测边界，不要再拿同一套模型重试：

### 判据：显存必须 ≥ 模型总参数量的 1.2 倍

图生视频不是「参数量小就能跑」。**双模型架构（如 WAN2.2 的 high_noise + low_noise 各 14G）要同时装进显存**，否则 ComfyUI 会把权重在 CPU↔GPU 之间反复搬运，fp8 精度被反复截断，**结果是脸崩而不是变慢**。

| 配置 | 显存占用表现 | 实测质量 |
|---|---|---|
| 双 14B 模型（共 28G）跑在 24G 卡上 | 占 19G 但**利用率 0%**（在搬权重） | 480p/10步 = 4分；720p/30步 = 2分（脸从第 2 秒开始垮） |

**「GPU 内存满了但利用率 0%」就是 offload 正在发生的信号**，不是「排队中」，也不是「在算」。看到这个不要等，直接判定这条路不可行。

### 三种本地模型的实际定位

| 模型 | 定位 | 能不能用 |
|---|---|---|
| **Sonic** | 唇同步（图 + 音频 → 嘴动） | ✅ 能用，**但它不是视频生成** —— 背景不动、身体不动、头会跟着算法晃 |
| **WAN2.2 14B** | 真图生视频 | ❌ 24G 卡装不下双模型，脸必崩 |
| **hunyuan_video** | 真图生视频（13G 单模型，装得下） | ⚠️ 取决于 ComfyUI 版本的 CLIPLoader 是否支持它的文本编码器 type（不支持时提交直接 400） |

判本地能不能上某个图生视频模型，**先查两件事再动手**：模型总量（单还是双）、以及 `curl /object_info/CLIPLoader` 的 `type` 枚举里有没有它要的那个值。两件任一不过，直接换云端，不要花时间调参。

### 超分救不了生成崩坏

脸崩、马赛克是生成阶段的问题，超分只做插值放大和边缘锐化。实测 4x 超分后再缩回 1080×1920，锐度反而**从 4.8 掉到 4.3** —— 因为 lanczos 把超分补出来的细节又抹平了一遭。**超分只在「输出尺寸小于目标尺寸」时有意义，且不修复形变。**

### Sonic 要用就必须这样配

本机唯一能产出可用动态的方案（画质 9 分，但只限「嘴动」）。两条参数是开关，错一个就卡死或报错：

| 参数 | 必须 | 错了会怎样 |
|---|---|---|
| `frames_per_batch` | **8**（不是 25） | 设为 25 时模型加载完就**死锁**：GPU 只占 2G、利用率 0%、永远不出帧 |
| `dtype` | **`fp16`**（不是 bf16） | bf16 报 `mat1 and mat2 must have the same dtype, but got Half and BFloat16` —— 模型权重是 fp16，不能混 |
| `min_resolution` | **512**（不是 768/1024） | 768 起 OOM |

单镜 512×896、约 205–241 秒。放大到 1080×1920 时**必须带 `unsharp=5:5:2.0`**：纯 lanczos 会把锐度从 2.9 打到 1.3，加 2.0 的 unsharp 能拉回 3.3。

### 给用户的话术

不要说「本机不行」。说清三层：**能生成视频**（确实出过 49 帧真运动）、**但质量过不了关**（脸崩）、**根因是显存装不下双模型而不是模型不会做**。然后给出真正的两条出路：换单模型（参数少一半、质量未知、要下载验证）或走云端。

## 可灵 vs 即梦 Seedance：按题材分，不是按参数分

用户问「哪个图生视频更强」时，不能只比参数 —— 两家强项不重叠，**选题材比选强弱重要**。

| 维度 | 可灵（快手） | 即梦 Seedance（字节） |
|---|---|---|
| **古风题材** | **明显更强**（中式建筑、服饰纹理、水墨意境还原度高） | 一般 |
| 画质 | **4K**，光影色彩强一档 | 2.0 为 1080p；2.5 原生 4K 10bit（生成阶段按 4K 算细节，非超分拉抻） |
| **人物一致性** | 2.6 支持音画同出、动作复刻 | **最强**（跨镜头记住角色长相） |
| 单次时长 | **上限 10 秒** | **30 秒** + 高保真时序延长 |
| 多模态参考 | 有限 | **最多 50 个**（图/视频/音频/白模/绿幕） |
| 物理真实 | — | 2.5 几何引导物理渲染（光照方向/色温/阴影约束） |
| 价格 | 720p 0.6 元/秒；1080p 音画同出 1.2 元/秒 | 纯生成 1 元/秒，渠道 5–8 折 |

**决策规则：**

- **古装／古风／历史题材 → 可灵。** 观众看帝王将相，看的是「像不像那个时代」，不是「物理对不对」。中式建筑、龙袍纹理、宫灯、编钟这些可灵还原得明显更好
- **现代题材 / 五个角色跨镜不能换脸 / 需要单镜超过 10 秒的连贯镜头 → 即梦 Seedance**
- 一首片子里需要长镜（人物从远处走到座位坐下这类）的通常只有 1–2 个，**不要为了这两镜全片换平台**

火山方舟上 Seedance 全套都在（`doubao-seedance-1-0-lite-i2v-*` / `-t2v-*` / `2-0-*` / `2-5-*`），但**模型可列不等于可用**：直接调会返回 `InvalidEndpointOrModel.NotFound`，必须先在控制台创建推理接入点。验收方式：调一次非零 body，拿到业务错误而不是 NotFound，才算开通成功。

## A 路线的提示词要点

图生视频时风格已由首帧锁定，提示词首句写 `Maintain the <style> of the reference image exactly.`，之后**只写动作 + 运镜 + 光**，不要重复描述画风。每条只给一种运镜；动词要具体（gazes / clutches / shuffles / tracks），不要 look / hold / sit。8 要素门禁见 skill `kling-prompt-quality-gate`。
