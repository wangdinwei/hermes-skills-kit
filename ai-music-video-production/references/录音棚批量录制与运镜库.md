# 录音棚批量录制：命名、运镜库、一歌多版排产

> 用在「同一个录音棚、很多首歌、一歌出多版、男女声各录」的批量生产。
> 上层成本结论与机位划分在 SKILL.md 的「录音棚单场景」一节，本文只写执行细节。

---

## 一、四段编码命名（文件名自带全部信息）

```
演员： CH-M01-短发硬朗-36     CH-F01-冷感都会-26     CH-F02-清爽少年感-25
棚：   SET-01-小型私人棚        SET-02-老式模拟棚       SET-03-日光木棚
机位： SET01-CAM-A ~ CAM-E
镜头： SET01-CAMA-SH03
曲目： SONG-<歌名>-V02        （V02 = Suno 出的第 2 条）
成片： <歌名>_V02_CH-M01_SET01-CAMA-SH03_r1.mp4
```

为什么必须这么编：

- 一首歌会出很多版，**V 编号是最先分流的东西**；没有它，四条音频两天后就分不清哪条是哪条
- **CH 后面跟性别**（M/F），男版女版才能直接筛
- 末级 `_r1` 记第几次重跑，废片不会混进成片
- 一个常驻项目装全部演员 + 全部棚（长期只增不删），每首歌用一个 group 分

定角后立刻用 `update_node(newName=...)` 换成正式编号；`idempotencyKey` 只能 ASCII，中文会让整个调用失败。

## 二、一歌多版排产（用户的核心用法）

用户会：同一首歌让 Suno 出好几遍 → 听几遍挑一遍 → **太好的那版男声录一遍、女声也录一遍**。
所以每次都要走同一条流水线，不能每首歌重新拍脑袋：

```
① Suno 出多版 → 全听 → 定一版（记 SONG-<歌>-V0X）
② demucs 分离纯人声（不能喂混音）
③ 按句切片 Q01…Qnn（一句一片）
④ 选角：男版 CH-M01 / 女版 CH-F01 各录一条
⑤ 合并切片成镜：每镜 12–15 秒（约 2–4 句），一镜一个运镜
⑥ 逐镜 generate_video：棚图 + 演员定妆 + 该镜音频切片
⑦ 合片：视频 -an 静音 + 原曲音轨 + 花絮镜 + 字幕（本地 ffmpeg）
```

**同一版录两个歌手的纪律：棚、机位、运镜、镜时长必须完全一致，只改「人物」那一段提示词。** 否则比不出谁唱得好、也剪不到一条时间线上。

**多版选听的交付方式**：同一遍出的两条，听完自己先给一个“这遍我选第几条”的推荐（副歌收尾稳、字没被压的那条），用户要的是判断而不是四个文件。

## 三、运镜库（8 条，按口型风险从低到高）

**机位动得越多，口型越容易漂。** 演唱型片子里运镜是调味，不是炫技。

| # | 名称 | 用法 | 时长 | 挂音频 | 风险 | 提示词一句 |
|---|---|---|---|---|---|---|
| 1 | 固定位 | 主唱长镜主体 | 12–15s | 挂 | 极低 | 机位完全固定，三脚架不动，只有人物微动 |
| 2 | 缓推 | 段落推进、副歌前 | 8–15s | 挂 | 低 | 单机位极缓推近，从胸上景到肩部特写，匀速，不摇不切 |
| 3 | 缓拉 | 尾段、情绪释放 | 8–12s | 挂 | 低 | 单机位极缓拉远，末尾停住 |
| 4 | 变焦点 | 设备前景 → 人脸 | 4–6s | 挂（半句） | 低 | 机位不动，焦点从前景调音台缓慢转到面部 |
| 5 | 侧移 | 制造空间、垫句间 | 6–10s | 挂 | 中 | 沿麦架缓慢横移约半米，人物始终在画面左三分之一 |
| 6 | 半环绕 | 副歌高潮，一次就够 | ≤8s | 挂 | 中高 | 以人物为圆心做三十度弧线移动，轨道平稳 |
| 7 | 轻升 | 情绪顶点 | 5–8s | 挂 | 中 | 从胸口高度升至眼平，垂直上移约三十厘米 |
| 8 | 手持微晃 | 花絮专用 | 2–4s | **不挂** | 无 | 手持轻微晃动跟随，不做稳定 |

**节奏公式（200 秒左右的歌）**：主歌 固定×2 + 变焦点×1｜副歌 缓推×1 + 半环绕×1 + 缓拉×1｜桥段 轻升×1｜尾段 固定×1 + 缓拉×1｜花絮插 4–6 个 2–3 秒，放段落交界。

换机位用**遮挡切**（人走过麦架 / 手挡镜头 / 身体出画）；同机位连续镜直接接。

**推近的尺度**：十秒推到头会变成“只剩鼻子和嘴”的大特写，过头。停在**胸上景 → 头肩**。

## 四、棚景：两件必须有、且能反复用的道具

**头戴监听耳机**（挂在麦架上 / 挂在脖子上，耳罩内绒有使用痕迹）+ **调音台上的监看屏**（显示抽象波形，不出可读文字）。

- 耳机是“真在录音而不是在对口型”最快被认出的信号；演员手里不用拿麦，双手能空出来做动作，脸也永远完整。
- 屏幕本身就是花絮容器：把**回放画面 / 波形 / 刚唱错的那一条**做成画中画塞进屏幕，**本地合成即可、0 生成成本**，真实感比再生成一个镜头强。

棚景 AI 破绽集中在设备上（推子排列乱、按键糊成一片、笔架融化、墙上时钟乱码）。**不要重出图**，设备一律做浅景深虚化前景、时钟/挂表用景别切掉；真要拍设备特写就单独出一张微距虚化图，别拿全景图裁。

## 五、演员海选与定角的判据（长期卡司，不是一次性选角）

试镜卡的统一条件（同一背景 / 同一支 3200K 侧光 / 同一件深灰圆领 / 同一 3/4 侧脸 / 都不笑）见 SKILL.md；这里只写选人的判断：

1. **不靠道具立人设**：长发 / 眼镜 / 络腮胡 / 灰白发都是强符号，会把歌路和年龄锁死。优先选“换件衣服就是另一个人”的脸。
2. **真实感优先于好看**：皮肤纹理、法令纹、胡茬、汗光是可长期用的必要条件；高光太平滑 = 塑料感的信号。
3. **男队视觉年龄 34–38 最值**：往上能演父辈、往下能演自己；比 24 岁学生脸有叙事重量，又不像 48 岁被年龄锁死。
4. **女队至少两个互补位**：一个冷感都会型 + 一个清爽少年感型。排除“太标准太安全”的通用女主脸——几十首 MV 全是同一张漂亮脸，观众会疲。
5. 定角时把“为什么淘汰其他人”一并说清，用户要的是导演判断，不是一个名单。

## 六、平台偶发：任务成功但节点没落进项目

批量 `create_node` 时会出现：`task_status` 报 SUCCEEDED、artifacts 里有 `node_key`，但 `read_project(section="nodes")` 里没有它，随后 `read_node` 报 `NODE_NOT_FOUND`。

处理：**每批出完立刻用 `read_project` 按名字逐个核对**，缺的换一个 `idempotencyKey` 重提（同 key 会重放旧的空结果）。
另有一种反向情形：节点在列表里但 `read_node` 读不到 URL，图只能在画布里看，本地下载不下来——这种直接告知用户“在画布上看”，不要反复重试。

**下载图不要只看一种 URL 特征**（`/image/` 或 `gen-save-img`）：递归按字段名 `url` / `urls` / `originalUrl` 收集，再按后缀过滤，比正则匹配整段 JSON 稳。

## 七、交付形态

- 出图海选阶段：**拼横向 contact sheet**（`ffmpeg -i a -i b … -filter_complex hstack=4`）再一次性判读，不要逐张问
- 定角阶段：把选中的 1–3 人拼一张“定角图”再发，配一张编号表说明每个人对应什么声线
- 音频试听阶段：同一首歌的多版**全部发**，但附自己的排序；用户要的是“你选哪个”而不是“你自己看着办”
