# AI 行业情报：文案核查 · 对标拆解 · 工具选品

用户跑 AI 科普赛道，会不断贴来三类东西：一段「本周 AI 大事」的竞品文案要你核**属实吗**、一个对标账号要你**拆打法**、一句「去 GitHub 看看有什么新收货」。这三件事的共同要求只有一条：**交付的每句话都要能指回原始出处，且分清「官方原话」和「二创加的戏」**。

## When to Use

- 用户贴来 AI 周报 / 竞品视频文案，问「属实吗」「核查一下」
- 准备选题或写口播稿时要引用第三方 AI 新闻、跑分、纪录
- 用户要「去 GitHub 看看有没有新工具 / 有什么收货」
- 拿到一个对标视频要拆它为什么能爆、我们该学哪几招

不适用：监控指定公司的定期新闻（用 `competitor-news-monitor`）；给自己的产出打引用编号（用 `grounded-citations`）。

## 第一原则：名字真 ≠ 话真

实测一份 809 字的 AI 周报，**29 个专名全部真实存在**（官方博客 / HF / GitHub 都能查到），但**至少 8 处口径是错的或被放大的**。所以「查到了这个名字」只完成一半，必须再做一遍口径核对。用户问「属实吗」时，合格的回答永远是分两层的：**专名层（存不存在、官方出处在哪）+ 口径层（数字、主体、时限、能力范围对不对）**。

## 核查流程

### 1 先把文案拆成两类清单

用正则抽出全部 `「…」` 专名，再按句号切成断言。**专名数 ≠ 断言数**：一个专名后面常挂 3 个数字，每个数字都是一条要核的断言。

```python
names = re.findall(r"「([^」]{2,30})」", txt)          # 专名清单
claims = [s for s in re.split(r"[。！？]", txt) if s.strip()]  # 断言清单
```

顺便量一遍节奏（汉字数、句数、字/秒），拆解竞品时直接复用（见下节）。

### 2 批量检索：一次 execute_code 打 8–11 个 query

不要一个 query 一次工具调用地磨。`execute_code` 里循环 `hermes_tools.web_search`，每个专名一条 query（中文 + 模型全名 + 关键数字），只打印 `title` + `description[:220]`：

```python
from hermes_tools import web_search
for q in qs:
    r = web_search(q, limit=3)
    print("###", q)
    for x in r.get("data",{}).get("web",[])[:3]:
        print("  -", x.get("title","")[:85])
        print("    ", (x.get("description") or "")[:200].replace("\n"," "))
```

description 只用来**筛出该打哪几页**，不能当证据。搜不到 ≠ 不存在，但连续两条 query 都无结果就标「存疑」并说明搜了什么。

### 3 打官方页，按关键词抽句子

官方博客 / 模型卡 / HF 模型页 / GitHub README / 吉尼斯官网 才算一手。`web_extract` 拿回来常常被截断，**不要整页读，按关键词列表过滤句子**：

```python
res = web_extract(urls, char_limit=9000)
keys = ["1M","million","#1","#3","benchmark","40x","99.99","open weights","license","开源","merges","6x"]
sents = [s for s in re.split(r"(?<=[。.!?；;\n])", content) if any(k in s for k in keys)]
```

关键词表按这一份文案的断言临时写，包含：每条声称的数字、每个带「开源/最强/登顶/纪录」的字眼。

### 4 判定：只用五个标签

| 标签 | 含义 |
|---|---|
| **属实** | 官方页面能找到同义表述，数字一致 |
| **口径放大** | 事情是真的，帽子是二创（子榜当总榜、官方没说的形容词） |
| **主体偷换** | 拿个案冒充全行业（单一客户、单一游戏、单一机型） |
| **旧闻** | 事件真实但时间不对，早已发生 |
| **未证实** | 官方没官宣（泄露/目录条目/传闻），或全网搜不到 |

### 5 交付格式：按「能不能照念」分组

三组固定顺序：**完全属实（可直接引用）→ 口径被放大（不能照念）→ 未证实/存疑**。每条一行：`专名 —— 判定 —— 一句依据（官方页面写了什么）`。最后给一句总账（「N 个专名零编造，M 处口径有问题」）+ 一条硬规矩（引用任何数字前回原始博客）。

不要写成逐条打分的评审报告，也不要为了显得严谨把能核实的也标未证实——用户要的是**哪几句能进我的口播稿**。

## 七种高频失真（命中就单独标出来）

1. **子榜当总榜**：声称某基准「登顶」而官网写的是第 3 / 26、另一页快照又写第 1 / 41 —— 榜单名 + 日期 + 子榜三样缺一不可。
2. **商业模型当开源**：声称「最强**开源**图像编辑」实为平台内商业模型、无开放权重。只要出现「开源」二字，就去 HF / GitHub 找权重，找不到就是这个错。
3. **单一对象当全行业**：声称「已接管 70% 客服通话」实为某一家公司客服；声称「让 Switch 游戏跑在手机上」实为一款游戏的兼容层。
4. **能力当产品**：声称「给个概念就自动生成带动画带语音的科普视频」实为一个把概念画成可拆可转等距图的技能，不产视频不配音。
5. **旧闻当本周**：纪录类（吉尼斯等）必查事件日期，官网会写明挑战日；半年以上的纪录不能进「本周」。
6. **硬件口径混谈**：8×GB200 / ~545 ms 与 单张 5090 / 83 FPS 是两个模型的能力，被并成一句「消费级实时」。
7. **泄露当发布**：云厂商目录出现「正式可用」条目 ≠ 官方发布。判据只看官方 changelog / models overview 上最新公开的那一个版本。

另外两类口头便宜也要标：**官方从没说的形容词**（官方只写「更强更快更短」而文案写「开源最强编程」）、**官方从没提的卖点**（某模型被称「没有安全围栏」而其 README 一字未提）。

### 视频/图像模型专项三条

1. **先查停服与关停，再谈强弱**。视频模型的寿命很短：厂商会直接把整条产品线（Web/App + API 分批）停掉并删数据，旧版本 preview 也会被强制迁移。判据只看官方 help center 的 deprecation/关停公告与 changelog；榜单上还挂着的模型名不等于还能调。写「谁最强」之前先确认它还在线。
2. **榜单有滞后，不能拿来判新品**。新模型发布后一到两周内往往还没进榜，此时榜首是上一代；同时榜单分「有音/无音」「文生/图生」子榜。报数时必须同时给「榜单名 + 子榜 + 抓取日 + 该模型是否已入榜」，否则就是子榜当总榜/旧模型当新品。
3. **「开源」与「可商用」必须分开写**。同一家公司的闭源 API 版和开放权重版常不同代（权重停在两代之前）；社区许可（如 LTX Community License）≠ Apache-2.0，进商业内容前要看条款，只学方法。验收动作：去 HF / GitHub 搜 `owner/model` 权重文件存不存在，搜不到就不许写「开源」。

## GitHub 选品流程

```bash
# 1) 新仓库按星扫（创建日 + 星数门槛）
curl -s --noproxy '*' -H "Accept: application/vnd.github+json" \
 "https://api.github.com/search/repositories?q=created:%3E2026-09-24+stars:%3E150&sort=stars&order=desc&per_page=15"
# 2) 按 topic 扫垂直领域
topic:ai-video+created:%3E2026-08-01 / topic:text-to-speech+created:%3E2026-06-01+stars:%3E100
```

- search API 未鉴权约 **10 次/分钟**，多个 query 之间 `sleep 2`；把 `full_name / stars / description[:110]` 三列打出来就够筛。
- **README 取法**：`raw.githubusercontent.com/<repo>/main|master/README.md` 经常返回空（分支名不同、主文件是 `README_ZH.md`、大小写不符）。可靠写法：
  ```bash
  curl -s --noproxy '*' -H "Accept: application/vnd.github.raw" https://api.github.com/repos/<owner>/<repo>/readme | head -c 1200
  ```
- 必查三项再推荐：**许可证**（PolyForm Noncommercial 等 = 方法可学、模板不能用于商业号）、**是否真开源**（权重在哪）、**star ÷ 仓龄**（一两周两万星多半是话题热度而非工程质量）。
- 输出按「对我们流水线有没有用」排序，每条一句：能替/补哪一步、成本、风险；末尾给「建议先动哪两个（不花钱的那些）」。不要罗列 20 个仓库让用户自己挑。

## 对标文案量化拆解

只量四个数：**汉字数 / 句子数 / 专名数 / 字每秒**，再算段落时长分布（每段字数 ÷ 语速）。

判据：`字/秒 ≈ 6.5–7` 是「念名单」流（无停顿、靠下一条更炸留人），`5.5–6` 是「讲因果」叙事流。同一份 809 字的稿子，叙事语速要 140 秒，名单流 120 秒就念完——**节奏差异就是内容形态差异**，不要用叙事语速去配名单流的稿子。

结论固定收在三招上，并明确**不改系列定位**：① 每条挂一个能被复述的硬数字；② 片头 3 秒定桩；③ 段与段之间一句话焊接。名单流拼信源速度与产能，不拼制作质量——用高成本镜头语言去追它是拿成本换别人的短板。

**BGM 判据（与 `ai-video-assembly` 的「全片无 BGM」不冲突，按形态分）**：

- 名单流 / 高频信息流（≈6.7 字/秒）：**必须配乐**，否则中段走神。118–124 BPM、铺在 −22 dB、每 4 段换一次 stem，「翻车/失败」那句掉鼓点。
- 叙事流（≈5.8 字/秒、靠语气吃饭）：**不加 BGM**，一铺音乐就盖住停顿。

## Pitfalls

- **只核专名不核口径**：等于没核查。回答必须是两层。
- **拿 search description 当证据**：description 只支持它字面写的那句，数字要回 `web_extract` 的页面正文。
- **整页读长文**：官方页多数被截断，正确姿势是关键词过滤句子，只核断言涉及的段。
- **把竞品文案的数字直接转述给用户**：即使用户说「这是视频里的」，未经核实的数字不能当事实复述——先核再写。
- **推荐工具前不看许可证**：非商用许可证的模板进了商业内容就是版权风险，先说清「只学方法」。
- **star 数当质量**：看 star ÷ 仓龄，并打开 README 确认真有可跑的代码与权重。
- **二手媒体当一手源**：模型名/跑分以官网博客、模型卡、HF 页面为准，科技媒体只用来定位。
